# AfterStorm 1.0 App Store Release Prep Plan

## Goal
Prepare the verified AfterStorm iOS build for a real App Store Connect submission without changing the approved product experience.

## Scope
1. Add release metadata and a submission checklist for AfterStorm 1.0.
2. Add a privacy manifest and export-compliance declaration appropriate to the current device-first architecture.
3. Add an archive/export helper that produces an App Store archive when Apple signing is available.
4. Add CI release-readiness checks that validate versioning, bundle identifiers, privacy URLs, privacy manifest inclusion, and archive configuration without requiring private Apple credentials.
5. Publish AfterStorm-specific privacy and support pages on the existing Storm & Me Official site.
6. Verify the website routes and the iOS simulator build after release-prep changes.

## Store Identity
- App name: AfterStorm
- Bundle ID: com.stormandme.afterstorm
- Widget bundle ID: com.stormandme.afterstorm.widget
- Version: 1.0
- Build: 1
- Privacy URL: https://stormandmeofficial.com/afterstorm/privacy
- Support URL: https://stormandmeofficial.com/afterstorm/support
- Marketing URL: https://stormandmeofficial.com/afterstorm

## Guardrails
- Do not alter quest logic, progression, onboarding, persistence behavior, visuals, navigation, or monetization.
- Do not commit Apple credentials, certificates, private keys, provisioning profiles, API keys, or team secrets.
- Signed App Store upload remains credential-gated; the repo should become ready for an authenticated Xcode/Transporter upload once the developer account is available.

## Verification
- Swift test suite passes.
- Xcode 26.3 simulator app + widget build passes.
- Release-readiness script passes.
- Public AfterStorm privacy/support routes return HTTP 200 after deployment.
- App Store archive script fails clearly when signing identity/team is absent rather than producing a misleading unsigned release artifact.

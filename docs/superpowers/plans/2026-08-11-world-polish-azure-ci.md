# AfterStorm World Polish + Azure CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move everyday CI from GitHub Actions to Azure Pipelines and upgrade The Block into a closer, more alive premium restoration diorama with staged lights, nature, weather, residents, and stronger restoration payoff.

**Architecture:** Keep GitHub as the source of truth. Add an Azure Pipelines YAML that runs core tests, deterministic asset generation, XcodeGen, and an iOS Simulator build on Microsoft-hosted macOS. Change GitHub Actions to manual-only for the expensive Xcode 27 smoke/release lane. For visuals, keep `WorldDioramaView` as the rendering boundary and derive all environment changes from restoration fraction/stages so every quest leaves a visible mark without adding new persistence models.

**Tech Stack:** SwiftUI, RealityKit, AfterStormCore, XcodeGen, Swift Package Manager, Azure Pipelines YAML, GitHub Actions.

## Global Constraints

- App baseline remains iOS 18.
- iOS 27 multimodal Foundation Models stays availability-gated and nonessential to core functionality.
- No new third-party runtime dependencies.
- No destructive streak or regression mechanics.
- Every quest completion must produce visible world feedback.
- GitHub Actions heavy macOS jobs must no longer run automatically on pushes/PRs.
- Azure is the normal development CI lane; GitHub Actions is a manual/release verification lane.
- Preserve Reduce Motion behavior and accessibility labels.
